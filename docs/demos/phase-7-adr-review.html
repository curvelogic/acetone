You ruled · merge-granularity gate

ADR-0035 — cell-wise merge.

ADR-0035You ruledno format bump

A node or edge changed on both sides merges property-by-property; only same-property divergence is a conflict.

The design record always promised this (Decision 4), but the code treated each whole record as opaque — so any node touched on both branches conflicted, even when the branches edited different properties. The flagship import-plus-curation workflow (import sets os_version, a human sets owner) conflicted on every run. Cell-wise merge is one of the two Dolt properties the design calls load-bearing.

WeighYou chose Option A (honour the spec) over Option B (amend the design to whole-record merge). It reshapes the conflict + resolve surface to per-property — a deliberate pre-freeze change so the 0.2 API never commits to the coarser model. The real work was the conflict representation and resolve semantics, not the value merge. Guarded by determinism + reindex property tests.

You ruled · enforcement mechanism

ADR-0036 — the query governor.

ADR-0036You ruledfrozen at 0.2

A deterministic work budget is the canonical cap; wall-clock time is an optional, off-by-default backstop.

The read engine had no governor — one untrusted query could hang or OOM (proven in Phase 2: a var-length walk over a 9-node graph never finished; range(0, 1e10) was OOM-killed at ~80 GB). Library embedding, which may feed end-user queries, makes this the top 0.2 hardening item.

WeighYou ruled the work budget over wall-clock-as-primary: it buys reproducibility — the same query over the same graph succeeds-or-errors identically on every machine, which is the only way the "no query exceeds the caps" property regime can exist. QueryLimits is frozen at 0.2. This is exactly where the security review caught the DISTINCT evasion — now closed (acetone-8ln).

Agent design · two frozen contracts

ADR-0037 & 0038 — identity and values.

Two things a stable API must never quietly change under a caller: which relationship you hold, and what a value means when it returns.

ADR-0037Agent design

Relationship identity from the edge key, not a row number.

The runtime used a positional e{index} that renumbered whenever the edge set changed — not stable across versions, no round-trip. id(), cross-version DELETE/SET, and diff/merge correlation all rested on an accident.

WeighThe on-disk key is already (src,type,dst,disc) — identity was derivable from data on disk, so no format change. Must be fixed before 0.2 freezes it.
ADR-0038You ruled

One opaque value carrier, not five native types.

The runtime lacked Bytes/temporal types, so a read→write round-trip retyped them to strings on disk. You chose an additive Value::Stored carrier over five native variants (which would need arms in all three comparison regimes and ~90 match sites).

WeighThe carrier is behaviourally identical to a string in every query semantic — zero read/comparison change, TCK stays green — it differs only in that writes recover the type. Faithful native types are the post-0.2 endgame.

Agent design · the API entry point

ADR-0039 — the Session query API.

ADR-0039Agent designfrozen at 0.2

A Session runs Cypher end-to-end — read, write, AT <version>, CALL acetone.* — and the CLI is routed through it.

All the parse → bind → adapt → execute → persist glue lived only in the CLI, so acetone-core — "the one dependency a library adds" — couldn't actually run a query. The library and the tool now share one path, so their behaviour cannot drift.

WeighThe notable call is layering: Repository lives in acetone-graph, which cannot depend on acetone-cypher — so a tempting Repository::query() would invert the crate stack and cycle. The Session lives in acetone-cypher instead (the lowest crate depending on both) and acetone-core re-exports it. This shape — run / run_with / query_at, typed QueryError with caret diagnostics — is frozen at 0.2.

Agent design · correctness-sensitive

ADR-0040 — a lazy, store-backed IndexSeek.

ADR-0040Agent designno format bump

An indexed read touches only the matching index entries and records, instead of materialising the whole version per query.

The Phase-5 in-memory seek still paid O(whole-version) to load every node and edge for every query — even one selecting a single row. This is the scalability win the secondary index exists for.

WeighTwo load-bearing correctness rules, both tested: (1) a lazy read can fail mid-query, so the first error is captured and surfaced (never a silent row-drop); (2) the index keys the raw value but a scan matches by rendering, so a string pin is served only for a declared non-deferred scalar (else it falls back to a scan) — keeping index-seek == scan always true. One documented divergence, reachable only by a raw write that Cypher and import both prevent.

Agent design · the merge story, completed

ADR-0041 & 0042 — lifecycle and curation.

ADR-0041Agent design

Every merge can be resolved, repaired, or aborted — and completion is re-validated.

Graph violations (a dangling edge, a constraint breach) had no path to completion and no escape hatch, and a completion commit wasn't re-checked — a resolution could silently commit a broken graph. Cell-wise merge sharpened this (an auto-merge can drop a required property).

WeighRe-validation reuses the same pure validate_merged — no new invariant surface. merge --abort is idempotent. Known v0.2 edge: persisted graph-violation entries can over-report until the commit clears them.
ADR-0042Agent design

Import curation via a one-directional mirror branch + merge.

Import is authoritative-replace, so a re-import blats human curation. Rather than a bespoke --merge import mode, the importer commits to an ingest branch and the human merges it in — cell-wise merge preserves a curation on a property the source doesn't carry.

WeighThe footgun to know: the mirror must stay one-directional (never merge main → ingest), or a curated property leaks into the merge base and a later re-import drops it silently. That discipline is a workflow property, not enforced by the store. Doesn't close dogfood exit-criterion #5.

Agent design · a smaller API addition

ADR-0043 — query advisories.

ADR-0043Agent designfrozen at 0.2

QueryResult gains an advisories field; the first note catches the schema-free undeclared-label trap.

A schema-free repository binds leniently, so MATCH (n:Nope) RETURN n returns 0 rows with no signal that Nope is unknown — a dogfooding user reads the empty table as "my query is wrong." Making it a hard error was rejected (it would break legitimate schema-free exploration and openCypher conformance).

WeighAn additive field on the frozen QueryResult, added now so it's part of 0.2. Zero change to rows / columns / exit status — the CLI prints advisories to stderr, so a scripted pipeline is untouched. The note fires only on the narrow trap (schema-free, empty result, label referenced, label absent from the graph). A general channel future diagnostics can reuse.

Flagged for your eye

ADR-0044 & 0045 — the two agent decisions.

Made autonomously this session to the full Gate-D-care standard (ADR + TDD + strongest-tier adversarial review), and surfaced here because they touch durability and the on-disk format's test surface.

ADR-0044Flagged

A linked worktree's uncommitted work survives a foreign git gc.

A linked worktree's workspace ref lives under refs/worktree/*, which git does not enumerate as a gc root from the main worktree (proven pure-git) — so the huo durability guarantee held only for the main worktree. Now mirrored into a common-store anchor git always sees; acetone gc prunes stale anchors.

WeighLocal-only ref, no format change; a new inherent overwrite_ref keeps the RefStore CAS-only contract intact. Residual: a narrow space-leak window (a removed worktree's stale anchor until the next acetone gc) — a leak, never data loss.
ADR-0045Flagged

Pin the shipped 64 KiB chunk profile in the goldens, additively.

The byte-exact goldens covered only the 16 KiB test profile, not the 64 KiB profile real repositories use. An empirical check was decisive: the old dataset collapses to a single leaf at 64 KiB, so flipping the default and re-pinning (option a) would have lost inner-node coverage.

WeighChose additive (option b) over a single canonical default — strictly more format coverage, no behavioural or benchmark change, ChunkParams::default() untouched. A cross-crate guard test keeps the two profiles honest. No format_version implication.
