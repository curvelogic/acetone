Context

What the tenant asked for

Phase 10 put acetone to work under a real project. That project's consolidated feedback (ADR-0072) named two capabilities the workbench model didn't yet cover:

  • Embeddable by a non-Rust host — process-per-command has a latency floor and no way to hold a warm repository. A host in any language needs to drive acetone over a stable interface, without linking a Rust library.
  • Multi-tenant within one repository — more than one graph in a single repo the user owns, each isolated, so a host can co-locate tenants without a repo sprawl.

ADR-0073 made these Phase 11. The governing principle for the daemon (ADR-0074, Greg-discussed): it adds no authority acetone doesn't already have as a process, and removes the temptation to add any — the host keeps auth, tenancy and transport policy; acetone is handed a directory.

What was done · 1 of 3

The daemon: a socket, not a server

acetone serve is one process per repository on a 0600 unix domain socket — the kernel ACL is the authentication; acetone holds no auth code. Length-prefixed JSON frames, so every language speaks it:

>>> import (source streams as chunk frames — no path over the wire)
>>> query MATCH (d:Demo) RETURN d.id → rows, then a typed ok
>>> query CREATE (a)-[:`relates to`]->(b) (autodeclare: coin the type)
>>> commit · branch · checkout · merge · resolve · status
  • No paths ever cross the wire — payload verbs (schema-apply, import) stream bytes as chunk frames; a streamed import stages to a daemon-private file the peer never names.
  • Bounded — the CLI's per-query governor + wall clock, a --max-concurrent execution bound, a separate connection cap, idle timeouts against stalled peers, a 100k-row daemon ceiling.
  • Recovers a dead writer's lock — the daemon (only) breaks a stale acetone-writer.lock when its pid names no live process, so it no longer crash-loops; a live lock is always refused.
Demonstrated: a stdlib-only Python client drives import → query → coin → schema-apply → status → commit → branch → merge against a live daemon, through the shipped binary — the criterion's four demo actions, no acetone library in sight.
What was done · 2 of 3

Multi-graph: n tenants, one repository

A second graph inits into an existing repository; --graph selects at open; each graph lives in its own ref namespace.

  • Per-graph workspace / merge-head refs — the acetone-42d family resolved with no format change: refs fall back per-graph → shared-global → pre-ADR-0014, and the first write migrates. The CAS hazard flagged in the design note was a false alarm — begin_write already decouples the CAS-expected ref value from the base content.
  • fsck / gc / migrate namespace-scoped — an operation on a graph touches only that graph's refs and objects; scoping is property-tested with n>1, cross-graph isolation asserted.
  • Isolation held under review — a torn 2nd-graph init that could read graph A's workspace via the shared-ref fallback was caught and closed (the is_sole_graph gate + migrate-at-init).
What was done · 3 of 3

Schema evolution: rename and merge a relationship type

The autodeclare ratchet (Phase 10) lets a host coin relationship types as it writes — which, unchecked, accretes near-duplicate predicates. Phase 11 ships the repair, in the migrate family, through the shipped CLI:

  • Rename rewrites the schema entry and the edge keys that carry the type.
  • Merge folds one type into another under an explicit, discriminator-aware same-pair collision policy.
The ratchet repair, end to end: coin relates-to, relatesTo and related as a host would drift into over a session, then heal all three into one canonical type — schema entry and every edge key rewritten, demonstrated as a test.

Problems & decisions · for ratification

The boundary agenda

  • ADR-0074 — the daemon's transport, protocol and lifecycle (a mid-phase decision, flagged for retrospective review): socket + framing + handshake + verb set + the no-paths rule + stale-lock recovery.
  • The session contract — your call (2026-08-10): a connection is a view onto the one shared per-worktree workspace, like concurrent CLI processes; implemented with a view to per-connection isolated sessions later. Review confirmed the wire protocol is model-agnostic, so that mode is a workspace-ref change, not a protocol change.
  • acetone-pz0k.8 (decision) — robust stale-lock recovery regardless of daemon count. The shipped recovery is safe under one-daemon-per-repo; two daemons on one repo is unsupported and reopens the double-writer window. Enforce daemon-exclusivity at serve startup, or move to a stale-immune flock/fcntl lock — your call.
Flagged follow-up — acetone-j6ui.4: the linked-worktree durability anchor is not graph-keyed, so two co-tenant graphs written from the same linked worktree share one anchor. Only defence-in-depth degrades (a foreign git gc of uncommitted linked-worktree chunks); every primary guarantee holds. Deferred on severity + fix-risk (the fix touches two prune-decision parse sites where an error is data loss) — it wants its own reviewed unit. Your call.
